# canvaaaas

Локальное приложение для правки больших иллюстраций по кускам: выделяю область, пишу промпт, область перерисовывается генеративной моделью и вклеивается обратно. Общение и интерфейс — на русском.

## Стек
- TypeScript (strict), Node ≥ 22.18. Сервер, ядро и скрипты — `.ts`, который Node запускает напрямую (встроенное удаление типов), поэтому там только «стираемый» синтаксис (`erasableSyntaxOnly`): без enum, namespace и параметров-свойств. Импорты — с расширением `.ts`.
- sharp (libvips) — все пиксельные операции. onnxruntime-node — выделение объектов (SAM 2.1): кодировщик на WebGPU, без него — на процессоре. Интерфейс — Preact + OpenSeadragon (тайлы), собирается Vite. Оболочка — Electron; её main собирается esbuild в `dist/electron/main.mjs`.
- Запуск: `npm start` (сборка + окно Electron), `npm run dev` (сервер + Vite на http://127.0.0.1:5173; `CANVAAAAS_PROVIDER=mock` — без платных генераций, `CANVAAAAS_OPEN=путь` — сразу открыть картинку). Для встроенного браузера есть `.claude/launch.json` (`canvaaaas-mock`, `canvaaaas-real`). Сервер для разработки после правок не перезапускается сам, а Vite в папке Dropbox иногда не замечает правку файла интерфейса: если изменение не видно — перезапустить `npm run dev`.
- Проверки: `npm run typecheck` (корень и `src/renderer`), `npm test` (vitest, `test/`). Проверка сборки Electron: `npm run build && npx electron . --smoke`.
- Приложение: `npm run install:mac` — electron-builder собирает `release/mac-arm64/canvaaaas.app`, скрипт подписывает его ad-hoc и кладёт в /Applications; проверка установленного: `/Applications/canvaaaas.app/Contents/MacOS/canvaaaas --smoke`. Настройки сборки — поле `build` в package.json; в зависимостях (`dependencies`) только то, что нужно main-процессу во время работы (sharp, undici, onnxruntime-node), всё, что собирает Vite, — в devDependencies. В `files` у `mac` и `win` — только своя платформа onnxruntime, и список там полный (`dist/**`, `package.json`): из одних исключений electron-builder кладёт в приложение весь проект. `--smoke` идёт со своим профилем, поэтому и при открытом canvaaaas. `release/` исключён из Dropbox.

## Git — только через GitHub
- Репозиторий живёт на GitHub: `origin` — https://github.com/gsa3d/canvaaaas, ветка `main`. Каждый коммит сразу отправлять туда (`git push`) — коммитов, которых нет на GitHub, не оставлять.
- Перед отправкой — `git fetch`: если на GitHub есть коммиты, которых нет здесь, сначала забрать их (`git pull --rebase`), а не перезаписывать.

## Ограничения, которые нельзя нарушать
- Генерация — Nano Banana (Gemini image) через прокси laozhang.ai или ChatGPT Images по подписке (ниже). Nano Banana — формат Google `generateContent`, ключ в `Authorization: Bearer`. Ключ вводится в приложении (`src/core/secrets.ts`): на macOS — Связка ключей (сервис `canvaaaas-laozhang`, аккаунт `api_key`, запись через stdin `/usr/bin/security`), на Windows — файл в userData, зашифрованный Electron safeStorage; `LAOZHANG_API_KEY` главнее. Ключ никогда не выводится в лог, консоль, ошибки или чат, не отдаётся интерфейсу обратно и не кладётся в папку проекта (она синхронизируется в Dropbox).
- ChatGPT Images — без API и без ключа: `chatgpt-codex.ts` запускает Codex CLI (`codex exec --json --ignore-user-config`, промпт через stdin), вошедший в ChatGPT пользователя; агент Codex вызывает встроенный инструмент картинок с нашим промптом и путями кусков. В ChatGPT сам не входить: вход делает пользователь. Картинка берётся из `~/.codex/generated_images/<thread_id>/`, ошибка инструмента (лимит подписки) — из журнала сессии `~/.codex/sessions/…/rollout-…-<thread_id>.jsonl`: в событиях `codex exec --json` генерации картинки нет. `OPENAI_API_KEY` из окружения Codex убирается, иначе он платил бы по API. Размер ответа инструменту не задаётся: ~1,57 Мп в пропорциях первой картинки, поэтому у модели одно «разрешение» `1,6 Мп`.
- Каждая генерация стоит денег (у ChatGPT — лимита подписки). Без явного согласия пользователя — не больше ~10 генераций за тестовый прогон. Все вызовы пишутся в журнал (`src/core/ledger.ts`).
- Модель не принимает маски. Маску делаем сами: вырезаем кусок с контекстом, генерируем, вклеиваем по маске с растушёвкой внутрь маски. Пиксели, где маска = 0, остаются побайтно равными оригиналу — это проверяет автотест.
- Картинки большие (8000×6000 и больше): пиксельная работа только на бэкенде, не в браузерном canvas. Исключения только показывают, а пиксели холста по-прежнему считает сервер: превью правки маски (ниже, не больше 2560 px) и маски объектов картинками (`/api/masks/…`, не больше 2048 px).
- Сервер слушает только 127.0.0.1, изменяющие запросы — только с заголовком `x-canvaaaas`.
- `node_modules/` и `work/` исключены из синхронизации Dropbox атрибутом `com.apple.fileprovider.ignore#P`.

## Устройство
- `src/providers/` — провайдеры генерации за общим интерфейсом `ImageProvider` (`types.ts`): `laozhang-gemini.ts` (Nano Banana 2 и Pro, undici с таймаутом 10 минут), `chatgpt-codex.ts` (ChatGPT Images через Codex CLI: поиск codex, в том числе внутри ChatGPT.app, не больше 2 запусков сразу; тест — с подставным codex), `mock.ts` для тестов и разработки. Модель в интерфейсе и API — `ModelChoice`: `flash`, `pro`, `chatgpt`. `director.ts` — директор (`PromptDirector`, ниже).
- Директор (флажок в форме правки и в форме повтора): перед генерацией ChatGPT смотрит на кусок, он же с подсветкой, набросок, весь холст с рамкой куска и референсы (`directorImages`) и расписывает задачу по-английски. Это `chatgptDirector` в `chatgpt-codex.ts` — тот же `codex exec`, но без инструмента картинок, ответ между `<task>` и `</task>`. Модель получает текст директора в TASK и слова пользователя следом (`buildPrompt`, `directed`); задача пользователя не меняется, интерфейс показывает оба текста. Вызов один на задачу: текст кэшируется по задаче и скрытию (`taskKey`), «Ещё варианты» с той же задачей его берут, слой помнит его (и в .caaa). Вызовы — в журнал с `kind: 'director'`, в счётчик генераций не входят. Ошибка директора — ошибка задачи, генерации не тратятся. У подставной модели — `mockDirector`.
- Шаги с критиком (`refine` в `session.ts`): с директором число в форме — не варианты разом, а шаги по очереди. Шаг 1 — с исходного куска; критик (`review` у `PromptDirector`, тот же `codex exec`, ответ `<done>` или `<fix>`, `criticPrompt`) смотрит кусок до, с подсветкой и после (`criticImages`) и говорит, что исправить; следующий шаг получает кусок с прежней попыткой, вклеенной по маске (`revise`, `blendFrame`), и замечания в FIX промпта. Шаги кончаются, когда критик говорит «готово» или их число вышло; последний шаг критик тоже смотрит. Каждый шаг — вариант (`base`, `fixes`, `critique`), после первого задача «Готово» и шаги можно принимать; «Остановить» (`stop`) обрывает идущий шаг, готовые остаются. «Ещё шаги» с той же задачей продолжают выбранный вариант — критик тогда обязан дать замечания (`mustFix`), его прежний ответ берётся, если маска та же; с поправленной задачей шаги идут с исходного куска. У «Ещё вариантов» слоя с директором первый шаг исправляет сам слой. Вызовы критика — в журнал с `kind: 'critic'`.
- Набросок (инструмент S, `src/core/sketch.ts`): цветные штрихи в координатах холста — подсказка модели, где и каким должно быть то, что в задаче; Alt стирает только набросок. Модель получает кусок с наброском отдельной картинкой после куска (и подсветки), до референсов. Слой помнит набросок для «Ещё варианты» (и в .caaa).
- `src/core/` — пиксельное ядро: `frame.ts` (рамка куска, пропорции модели и разрешение ответа; без Node — его же импортирует интерфейс для подсказки «разрешения не хватает / с запасом» до генерации), `mask.ts` (bbox, растушёвка, подсветка), `mask-shapes.ts` (фигуры выделения → маска), `expand.ts` (расширение маски по правке), `edit-region.ts` (подготовка куска, слой правки, вклейка), `document.ts` (исходник + слои правок, пирамида тайлов, undo/redo), `image-file.ts` (можно ли перезаписать файл без потерь, кодирование, атомарная запись), `project.ts` (свой формат .caaa: подпись, JSON-описание, PNG исходника и каждого слоя с маской), `recent.ts` (недавние файлы и миниатюры в папке данных приложения), `ledger.ts` (журнал генераций), `secrets.ts` (ключ).
- Слои (панель «Слои»; в коде — `patches`, `history`): слой хранит ответ модели на весь прямоугольник куска и маску до растушёвки, поэтому маску можно править и после принятия (`setPatchMask`): ластик открывает холст под слоем, кисть возвращает пиксели модели, в том числе за краем исходного выделения. Правка маски — обычный шаг ⌘Z; правки масок, отмена и повтор на сервере идут строго по очереди (`serialDoc`). Отмена помнит 100 шагов. Удаление слоя (`removePatch`) — тоже шаг ⌘Z.
- Правка маски слоя или задачи видна сразу (`src/renderer/mask-edit.ts`): сервер отдаёт картинки участка — холст под слоем, слои над ним (`regionAround`), ответ модели и маску (`/api/history/:id/edit/…`, `/api/jobs/:id/edit/…`, номер состояния маски в заголовке `x-canvaaaas-version`), а браузер сам смешивает их по маске той же `featherAlpha`, что у сервера; мягкая кисть — отпечатки с тем же профилем, что у размытой линии сервера. Поэтому после ответа сервера картинка не меняется, а синей заливки маски нет — только контур. Свои мазки маску из сервера не перезапрашивают; её перезапрашивают отмена и «Расширить по правке» (`maskChanged`) и ошибка мазка. Законченная правка держит превью, пока холст или слой задачи не догонят последний мазок. Сервер пересчитывает только участок около мазка (`applyShapesRegion`, `featherAlphaRegion` — побайтно как целиком, это проверяет тест).
- «Скрыть от модели то, что под маской» (`hide`): модель получает один кусок, где область залита серым (`guide: 'blank'`), и рисует её заново, не держась за прежнее. Слой помнит это (и в .caaa), «Ещё варианты» слоя идут так же.
- Повтор с поправкой (`RedoChange`): карандаш у задачи в очереди и у слоя открывает её задачу и флажок скрытия; новые варианты идут к прежним (`moreVariants`, `patchVariants`, у задачи с ошибкой — `retry`), промпт и картинки модели собираются заново (`retarget`), кусок и маска прежние. Каждый вариант помнит свою задачу и скрытие — с ними ложится слой. Пока идут новые варианты, задача остаётся «Готово»: прежние можно сравнивать и принимать. После отправки форма новой правки очищается (задача, референсы, флажок), модель, разрешение и число вариантов остаются.
- «Ещё варианты» слоя (`patchVariants`) — задача в очереди с той же задачей, маской слоя, моделью, разрешением и референсами (слой их помнит, в .caaa тоже); модель видит холст под слоем (`crop` в `prepareEdit`, `regionWithout`), нынешний слой — вариант №1 для сравнения. Принятый вариант ложится на место слоя в стопке (`replacePatch`), превью замены — участок холста, каким он станет (`regionReplaced`), а не слой поверх прежнего.
- Тайлы холста кэшируются браузером навсегда, а `rev` у каждого документа начинается с 1, поэтому в адресе тайла есть и id документа.
- Свой формат — проект `.caaa` (`project.ts`): исходник, все слои (и скрытые) с RGBA и маской до растушёвки, стиль, dpi; после открытия холст побайтно тот же, история отмены пустая. PNG исходника кэшируется по буферу `doc.base`, поэтому повторное сохранение быстрое. В Finder `.caaa` открывается двойным щелчком (`fileAssociations` в package.json, `open-file` в `main.ts`).
- Сохранение: проект `.caaa` «Сохранить» пишет без вопросов. Картинка со слоями сначала спрашивает «Сохранить слои?»: в .caaa или слить в картинку; после записи картинкой (`flattened`) больше не спрашивает до открытия другого документа. «Экспортировать картинку…» пишет копию, не меняя файл документа. Картинку «Сохранить» перезаписывает (так решил пользователь), но только если это без потерь — `inspectImage` запрещает перезапись при прозрачности, >8 бит, не-sRGB профиле, CMYK, TIFF, нескольких кадрах; тогда — «Сохранить как». Запись через временный файл и rename. Окна выбора файла и вопросы «Сохранить изменения?» даёт `Host` (`session.ts`), его реализует Electron; у сервера для разработки окон нет — там «Сохранить как» скачивает PNG. Недавние файлы сервера для разработки — отдельный список (`<папка данных>/dev`). «Не сохранено» считается по содержимому: `contentKey` документа (включённые правки по порядку) сравнивается с сохранённым, поэтому отмена до сохранённого состояния снимает метку; у проекта .caaa ещё и стиль. Закрытие окна и выход (⌘Q) с несохранённым спрашивают «Сохранить изменения?» — это проверяет `--smoke`.
- `src/server/` — `session.ts` (документ и очередь задач: не больше 2 одновременно; ответы моделей хранятся, поэтому смена маски — бесплатная перевклейка), `app.ts` (HTTP на 127.0.0.1: проверка Host и заголовок `x-canvaaaas` у изменяющих запросов), `main.ts` (сервер без Electron).
- `src/shared/api.ts` — типы API, общие для сервера и интерфейса, и команды меню (`AppCommand`). `src/renderer/` — интерфейс: `viewer.ts` (OpenSeadragon + оверлей выделения и наброска; прокрутка двумя пальцами и колесо двигают картинку, щипок и ⌘ + колесо масштабируют; клавиатура OpenSeadragon выключена — её R, S, W, A, D, F спорят с клавишами инструментов), `App.tsx`. Иконки — только Tabler (`@tabler/icons-preact`), своих SVG не рисуем.
- Тексты в интерфейсе — короткие подписи без объяснений. Пояснение, если без него никак, — за значком «?» рядом (`Help` в `App.tsx`: окно по щелчку, в `document.body`). Снять выделение — ⌘D (меню «Правка»), Esc или крестик на плашке «Выделение»; ⌘Z в форме убирает последнюю фигуру или штрих наброска.
- Мягкая кисть (`softness` у мазка, 0..1) — только при правке маски слоя или задачи, выделение всегда жёсткое. Сервер растеризует её в `mask-shapes.ts` размытием по Гауссу (линия уже на половину зоны затухания, σ = зона/5), превью в `viewer.ts` повторяет то же через `ctx.filter`. `src/electron/main.ts` — окно и меню: пункты меню шлют `AppCommand` в окно событием `canvaaaas-command`, их сочетания клавиш не регистрируются (`registerAccelerator: false`) и обрабатываются интерфейсом — кроме «Отменить»/«Повторить», без которых на macOS не работает отмена в полях ввода. Настройки — только из меню (⌘,), не кнопкой в интерфейсе. «Открыть…» — тоже только из меню (⌘O) и со стартового экрана, в верхней полосе его нет.
- Промпт для модели собирает `buildPrompt` (`edit-region.ts`): задача первой и как обязательная — осторожная формулировка («верни картинку, всё сохрани») давала ответы почти без изменений. В статистике варианта есть `insideChangedPct`; ниже 2% интерфейс предупреждает, что правка не случилась.
- Объекты (`DocObject` в `document.ts`, `objects.ts`): имя и маска поверх пикселей холста, дерево частей (`parent`). Новый объект встаёт частью самого маленького, внутри которого лежит, и забирает себе объекты того же уровня, лежащие в нём (`placeObject`): поэтому «объединить» — это сохранить объект из нескольких (⌘J); удалённый отдаёт части своему родителю. Записи объектов не меняются на месте, любое изменение — шаг ⌘Z (`setObjects`); в .caaa маски — PNG. Объект в выделении — фигура `kind: 'mask'` (`obj:id` или id маски под щелчком), задача берёт маски сразу (`resolveShapes`), слой правки помнит объект (`object`). Объекты входят в «не сохранено»; картинкой их не сохранить — «Сохранить» спрашивает, как про слои.
- Выделение объектов (`segment.ts`, `segment-model.ts`, `server/segmentation.ts`): SAM 2.1 base+ (Meta, Apache 2.0), ONNX-сборка AnyLabeling. Веса ~290 МБ не в сборке: скачиваются по кнопке в папку данных приложения (`models/`), не в Dropbox, архив сверяется по SHA-256 и распаковывается своим разбором zip; `CANVAAAAS_SAM_DIR` — другая папка. Признаки считаются по видимой части холста (по всей картинке края объектов — каша), заранее, когда вид остановился (`/api/segment/view`, устаревший вид не считается); подсветка под курсором — `hover.png`, щелчок даёт до 3 уровней «деталь / часть / целое» (`levels`), мелкий для вида объект уточняется вторым проходом (`refine`). Маски декодера чистятся на сетке (`cleanLogits`): мелкие дыры внутри (на штриховке — «шахматкой») заделываются, крошки вокруг убираются, крупный проём остаётся. Инструмент «Объект» (W): щелчок — по режиму выделения (ниже), туда же или [ ] — уровень мельче или крупнее (и переключатель «Деталь / Часть / Целое» на панели), рамка — объект внутри неё. «По линиям» (`snap` у `PickRequest` и уточнения) привязывает маски уровней к линиям рисунка. При «Добавить» и «Вычесть» щелчок несёт выделение (`op`, `selection`): если уровень модели его не меняет (весь уже выделен), первым идёт ближайший мельче, который меняет, — крупнее нельзя, иначе щелчок внутри выделенного добавлял бы фон; не меняет никакой — `unchanged`, интерфейс так и говорит. Итоги разведки — `docs/recon-objects.md`.
- Панель настроек инструмента — строка над холстом (`optbar` в `App.tsx`): у инструментов выделения режим «Новое / Добавить / Вычесть» (`SelectOp`; Shift и ⌘ — добавить, Alt — вычесть на время щелчка, у всех инструментов как в Photoshop; кисть не заменяет, ластик всегда вычитает) и «Край ±px» (`/api/selection/edge`: всё выделение одной маской шире или уже, считается от выделения до первого сдвига края); у правки маски слоя или задачи — размер, мягкость и «Готово». Слева — только инструменты. Настройки инструментов помнятся в localStorage окна (`usePref`).
- Линии рисунка (`src/core/lines.ts`): светлые области между тёмными линиями, щели до 2·gap px закрыты (`lineMap`). `snapToLines` — область, которую маска покрывает почти целиком, берётся вся, едва задетая выбрасывается, протёкшая через щель остаётся как в маске, линии рядом со взятым — контур; у мазка кисти (`reach`, «По линиям» у кисти, `/api/selection/snap`) нарисованное остаётся, клетки, которые он почти накрыл, добавляются. «Палочка» (Q, `wand`, `/api/segment/wand`): область той же яркости вокруг щелчка в видимой части — допуск, щели, смежные, с контуром; щелчок на штрих штриховки переносится в светлое рядом. Маски палочки, края и мазков хранятся там же, где маски объектов под щелчком (`Segmentation.keep`).
- Отделить объект (`detachObject`, `placeDetached` в `session.ts`): задача в очереди с маской объекта, раздутой на 2% (`fillGrow`, `dilate`), со скрытием и задачей `FILL_TASK` — модель дорисовывает фон. Принятый вариант одним шагом ⌘Z (`batch` в `document.ts`) ложится слоем фона, а объект — своим слоем сверху (`lifted`: пиксели холста под маской, раздутой на 2 px); маска объекта с тех пор — маска этого слоя. Дальше без генераций: «Сдвинуть» (V) тянет слой (`movePatch`, `moveObject` — вместе с частями объекта, целиком на холсте; превью в браузере — `below` и `cutout.png` слоя), глаз скрывает, ластик по маске слоя стирает часть (и из маски объекта), корзина убирает с холста вместе со слоем и частями. Правка отделённого объекта ложится в его слой, туда, куда его сдвинули (`mergeLifted`); «Ещё вариантов» у такого слоя нет.
- Маска объекта следует за правкой (`followObjects`, `remask`): после «Принять» объекты, чей край правка задела (`touchedEdge`: изменённые пиксели у границы маски; окно глубоко внутри дома — нет), пересчитываются по рамке старой маски вместе с тем, что изменилось рядом, и самой старой маской подсказкой — нейтральной там, где пиксели поменялись (`unsure`), иначе маска не растёт за объектом. Пересчёт — в том же шаге отмены, что и правка (`historyTop`, `join`), если после неё ничего не делали; не нашёлся — объект помечается `lost`. Скрытие слоя и правка его маски маски объектов не пересчитывают; маски отделённых объектов не пересчитываются вовсе.
- `src/cli/edit-region.ts` — CLI правки области. `scripts/recon.ts` — разведка шага 0, итоги в `docs/recon.md`. Разведка выделения объектов (SAM 2.1 в onnxruntime-node) — `docs/recon-objects.md`.
