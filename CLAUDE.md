# canvaaaas

Локальное приложение для правки больших иллюстраций по кускам: выделяю область, пишу промпт, область перерисовывается генеративной моделью и вклеивается обратно. Общение — на русском; интерфейс — на английском, а на русском, если система по-русски или так выбрано в настройках (ниже, «Язык»).

## Стек
- TypeScript (strict), Node ≥ 22.18. Сервер, ядро и скрипты — `.ts`, который Node запускает напрямую (встроенное удаление типов), поэтому там только «стираемый» синтаксис (`erasableSyntaxOnly`): без enum, namespace и параметров-свойств. Импорты — с расширением `.ts`.
- sharp (libvips) — все пиксельные операции. onnxruntime-node — выделение объектов (SAM 2.1): кодировщик на WebGPU, без него — на процессоре. Интерфейс — Preact + OpenSeadragon (тайлы), собирается Vite. Оболочка — Electron; её main собирается esbuild в `dist/electron/main.mjs`, рядом — поток выделения объектов `segment-worker.mjs`.
- Запуск: `npm start` (сборка + окно Electron), `npm run dev` (сервер + Vite на http://127.0.0.1:5173; `CANVAAAAS_PROVIDER=mock` — без платных генераций, `CANVAAAAS_OPEN=путь` — сразу открыть картинку). Для встроенного браузера есть `.claude/launch.json` (`canvaaaas-mock`, `canvaaaas-mock-en` — интерфейс по-английски, `canvaaaas-real`; `canvaaaas-mock-5194` — когда 5173 занят другой сессией: интерфейс собирается в `work/ui-5194`, сервер с подставной моделью раздаёт его на 5194, картинку туда открывают `POST /api/doc/upload`). Сервер для разработки после правок не перезапускается сам, а Vite в папке Dropbox иногда не замечает правку файла интерфейса: если изменение не видно — перезапустить `npm run dev`.
- Проверки: `npm run typecheck` (корень и `src/renderer`), `npm test` (vitest, `test/`). Проверка сборки Electron: `npm run build && npx electron . --smoke`.
- Установщики для GitHub: `npm run dist:mac` — `release/canvaaaas-<версия>-mac-arm64.dmg` и `.zip` (Apple Silicon: у onnxruntime-node нет darwin-x64), пакет до упаковки подписывается ad-hoc в `scripts/after-pack.cjs` (`mac.identity: null` — electron-builder сам не подписывает); `npm run dist:win` — `release/canvaaaas-<версия>-windows-x64-setup.exe`: на Mac `scripts/dist-win.ts` собирает его в копии проекта `work/win-build` с `npm ci --os=win32 --cpu=x64 --ignore-scripts` (в `node_modules` проекта Windows-версии sharp не ставить) и `npmRebuild=false`. Установщик Windows здесь не запустить — проверяет пользователь. Проверка `.dmg`: смонтировать (`hdiutil attach`) и запустить из него `canvaaaas.app/Contents/MacOS/canvaaaas --smoke`, с `CANVAAAAS_LANG=en` — тоже.
- Релиз: GitHub Actions не использовать (лимиты исчерпаны) — всё собирается здесь. Версия — `version` в package.json; потом `gh release create v<версия>` с `.dmg`, `.zip` и `-setup.exe` из `release/` (без `.blockmap` и `latest*.yml`: автообновления нет). README.md (английский) и README.ru.md — описание и установка для GitHub: меняется то, что в них описано, — обновлять оба. Лицензия — MIT (`LICENSE`).
- Приложение: `npm run install:mac` — electron-builder собирает `release/mac-arm64/canvaaaas.app`, скрипт подписывает его ad-hoc и кладёт в /Applications; проверка установленного: `/Applications/canvaaaas.app/Contents/MacOS/canvaaaas --smoke`. Настройки сборки — поле `build` в package.json; в зависимостях (`dependencies`) только то, что нужно main-процессу во время работы (sharp, undici, onnxruntime-node), всё, что собирает Vite, — в devDependencies. В `files` у `mac` и `win` — только своя платформа onnxruntime, и список там полный (`dist/**`, `package.json`): из одних исключений electron-builder кладёт в приложение весь проект. `--smoke` идёт со своим профилем, поэтому и при открытом canvaaaas. `release/` исключён из Dropbox.

## Git — только через GitHub
- Репозиторий живёт на GitHub: `origin` — https://github.com/gsa3d/canvaaaas, ветка `main`. Каждый коммит сразу отправлять туда (`git push`) — коммитов, которых нет на GitHub, не оставлять.
- Перед отправкой — `git fetch`: если на GitHub есть коммиты, которых нет здесь, сначала забрать их (`git pull --rebase`), а не перезаписывать.

## Ограничения, которые нельзя нарушать
- Генерация — Nano Banana (Gemini image) через прокси laozhang.ai или ChatGPT Images по подписке (ниже). Nano Banana — формат Google `generateContent`, ключ в `Authorization: Bearer`. Ключ вводится в приложении (`src/core/secrets.ts`): на macOS — Связка ключей (сервис `canvaaaas-laozhang`, аккаунт `api_key`, запись через stdin `/usr/bin/security`), на Windows — файл в userData, зашифрованный Electron safeStorage; `LAOZHANG_API_KEY` главнее. Ключ никогда не выводится в лог, консоль, ошибки или чат, не отдаётся интерфейсу обратно и не кладётся в папку проекта (она синхронизируется в Dropbox).
- ChatGPT Images — без API и без ключа: `chatgpt-codex.ts` запускает Codex CLI (`codex exec --json --ignore-user-config`, промпт через stdin), вошедший в ChatGPT пользователя; агент Codex вызывает встроенный инструмент картинок с нашим промптом и путями кусков. В ChatGPT сам не входить: вход делает пользователь. Картинка берётся из `~/.codex/generated_images/<thread_id>/`, ошибка инструмента (лимит подписки) — из журнала сессии `~/.codex/sessions/…/rollout-…-<thread_id>.jsonl`: в событиях `codex exec --json` генерации картинки нет. `OPENAI_API_KEY` из окружения Codex убирается, иначе он платил бы по API. Размер ответа инструменту не задаётся: ~1,57 Мп в пропорциях первой картинки, поэтому у модели одно «разрешение» `1,6 Мп`.
- Каждая генерация стоит денег (у ChatGPT — лимита подписки). Без явного согласия пользователя — не больше ~10 генераций за тестовый прогон. Все вызовы пишутся в журнал (`src/core/ledger.ts`).
- Модель не принимает маски. Маску делаем сами: вырезаем кусок с контекстом, генерируем, вклеиваем по маске с растушёвкой внутрь маски. Пиксели, где маска = 0, остаются побайтно равными оригиналу — это проверяет автотест.
- Картинки большие (8000×6000 и больше): пиксельная работа только на бэкенде, не в браузерном canvas. Исключения только показывают, а пиксели холста по-прежнему считает сервер: превью правки маски (ниже, не больше 2560 px) и маски объектов картинками (`/api/masks/…`, не больше 2048 px).
- Сервер слушает только 127.0.0.1, изменяющие запросы — только с заголовком `x-canvaaaas`.
- `node_modules/` и `work/` исключены из синхронизации Dropbox атрибутом `com.apple.fileprovider.ignore#P`.

## Устройство
- `src/providers/` — провайдеры генерации за общим интерфейсом `ImageProvider` (`types.ts`): `laozhang-gemini.ts` (Nano Banana 2 и Pro, undici с таймаутом 10 минут), `chatgpt-codex.ts` (ChatGPT Images через Codex CLI: поиск codex, в том числе внутри ChatGPT.app, а на Windows — `codex.exe` за обёрткой `codex.cmd` от npm и pnpm (`codexBehindShim`: путь к `codex.js` из обёртки → пакет `@openai/codex-win32-x64`) и в папках установщика Codex, при запуске его `bin` и `codex-resources` — в начало PATH (`withCodexDirs`); не больше 2 запусков сразу; тест — с подставным codex, поиск на Windows — `test/codex-find.test.ts`), `mock.ts` для тестов и разработки. Модель в интерфейсе и API — `ModelChoice`: `flash`, `pro`, `chatgpt`. `director.ts` — директор (`PromptDirector`, ниже).
- Директор (флажок в правке, у поправки задачи версии — свой): перед генерацией ChatGPT смотрит на кусок, он же с подсветкой, набросок, весь холст с рамкой куска и референсы (`directorImages`) и расписывает задачу по-английски. Это `chatgptDirector` в `chatgpt-codex.ts` — тот же `codex exec`, но без инструмента картинок, ответ между `<task>` и `</task>`. Модель получает текст директора в TASK и слова пользователя следом (`buildPrompt`, `directed`); задача пользователя не меняется, интерфейс показывает оба текста. Вызов один на задачу: текст кэшируется по задаче и скрытию (`taskKey`), «Ещё варианты» с той же задачей его берут, слой помнит его (и в .caaa). Вызовы — в журнал с `kind: 'director'`, в счётчик генераций не входят. Ошибка директора — ошибка задачи, генерации не тратятся. У подставной модели — `mockDirector`.
- Шаги с критиком (`refine` в `session.ts`): с директором число в форме — не варианты разом, а шаги по очереди. Шаг 1 — с исходного куска; критик (`review` у `PromptDirector`, тот же `codex exec`, ответ `<done>` или `<fix>`, `criticPrompt`) смотрит кусок до, с подсветкой и после (`criticImages`) и говорит, что исправить; следующий шаг получает кусок с прежней попыткой, вклеенной по маске (`revise`, `blendFrame`), и замечания в FIX промпта. Шаги кончаются, когда критик говорит «готово» или их число вышло; последний шаг критик тоже смотрит. Каждый шаг — вариант (`base`, `fixes`, `critique`) и сразу версия слоя; «Остановить» (`stop`) обрывает идущий шаг, готовые остаются. «Ещё шаги» с той же задачей продолжают выбранный вариант — критик тогда обязан дать замечания (`mustFix`), его прежний ответ берётся, если маска та же; с поправленной задачей шаги идут с исходного куска. У «Ещё вариантов» версии с директором первый шаг исправляет саму версию. Вызовы критика — в журнал с `kind: 'critic'`.
- Набросок (инструмент S, `src/core/sketch.ts`): цветные штрихи в координатах холста — подсказка модели, где и каким должно быть то, что в задаче; Alt стирает только набросок. Модель получает кусок с наброском отдельной картинкой после куска (и подсветки), до референсов. Слой помнит набросок для «Ещё варианты» (и в .caaa).
- `src/core/` — пиксельное ядро: `frame.ts` (рамка куска, пропорции модели и разрешение ответа; без Node — его же импортирует интерфейс для подсказки «разрешения не хватает / с запасом» до генерации), `mask.ts` (bbox, растушёвка, подсветка), `mask-shapes.ts` (фигуры выделения → маска), `expand.ts` (расширение маски по правке), `edit-region.ts` (подготовка куска, слой правки, вклейка), `document.ts` (исходник + слои правок, пирамида тайлов, undo/redo), `layer-tree.ts` (группы слоёв: дерево и перестановки), `image-file.ts` (можно ли перезаписать файл без потерь, кодирование, атомарная запись), `project.ts` (свой формат .caaa: подпись, JSON-описание, PNG исходника и каждого слоя с маской), `recent.ts` (недавние файлы и миниатюры в папке данных приложения), `ledger.ts` (журнал генераций), `secrets.ts` (ключ).
- Слои и версии (панель «Слои»; в коде слой — `DocObject`, `objects`, версия — `Patch`, `patches`, в API — `objects` и `history`): слой — кусок картинки по маске со своими пикселями поверх остального (как в Photoshop), с видимостью (`hidden`) и текущей версией (`current`; нет — исходник: копия того, что было видно, когда слой завели, `lifted`). Части (`parent`) бывают только у слоёв из старых проектов: новые слои ни во что не вкладываются. Версия хранит ответ модели на весь прямоугольник куска и маску до растушёвки, поэтому маску версии можно править и после (`setPatchMask`): кисть в режиме «Скрыть» открывает то, что под ней, в режиме «Вернуть» возвращает пиксели модели, в том числе за краем исходного выделения; «Расширить по правке» (`expandVersion`) сравнивает с холстом без версии, с допуском: сдвиг линий до 4 px изменением не считается (`tolerance` в `expand.ts` — ChatGPT перерисовывает весь кусок со сдвигом, и пиксель в пиксель маска разливалась по нему целиком), а к краю куска, за которым холст продолжается, маска вплотную не подходит (`closed`), иначе вклейка обрывается там без растушёвки. Видно только текущую версию видимого слоя (`sync`); порядок на холсте (`drawOrder`, `stack`) — слои по порядку появления, новый сверху, часть не ниже целого, заплатка фона прямо под своим слоем; порядок меняют перетаскиванием в «Слоях» (`moveLayer`, `/api/layers/:id/move`: слой или группа — в группу или корень прямо над другим или под все, слой — с частями, заплатка фона едет за ним сама; шаг ⌘Z). Группы слоёв, как папки в Photoshop (`DocGroup`, `doc.groups`, `group` у слоя и у вложенной группы; `src/core/layer-tree.ts`): имя и видимость (скрытая группа скрывает всё, что в ней, — `visibility()` в `document.ts`); своего места в стопке у группы нет — её слои лежат подряд, и где они, там и она; группа без слоёв уходит сама (`liveGroups` в `setObjects`, тем же шагом ⌘Z). Перестановки — над деревом: `buildTree` → `moveNode` / `groupNodes` / `ungroupNode` / `insertTop` → `flatten`, поэтому слои группы всегда подряд. «Сгруппировать» (⌘G, `groupLayers`) — выбранная группа, слои в выделении или тот, в котором работают: новая группа на месте верхнего; «Разгруппировать» (⇧⌘G) — её слои на её место; «Удалить со слоями» (`deleteGroup`). Щелчок по группе (`activeGroup` в `App.tsx`, `selectGroup`) — её видимые слои в выделение, а новый слой (генерация не в слое, ⌘J, ⌘⇧J) ложится сверху в неё (`group` у задачи и у `/api/objects`; у ⌘J в слое — в его группу); объединённый слой — в группе верхнего. Смена версии, скрытие, удаление версии (`removePatch`: слой показывает предыдущую) и слоя (`deleteObject`) — шаги ⌘Z; несколько изменений одним шагом — `batch`. Правки масок, отмена и повтор на сервере идут строго по очереди (`serialDoc`). Отмена помнит 100 шагов. ← и → переключают версии слоя, в котором работают, «\» показывает исходник всей картинки, пока его держат (`/api/doc/base/…`).
- Правка маски версии видна сразу (`src/renderer/mask-edit.ts`): сервер отдаёт картинки участка — холст под версией, версии над ней (`regionAround`), ответ модели и маску (`/api/history/:id/edit/…`, номер состояния маски в заголовке `x-canvaaaas-version`), а браузер сам смешивает их по маске той же `featherAlpha`, что у сервера; мягкая кисть — отпечатки с тем же профилем, что у размытой линии сервера. Мазок ложится прямо в прозрачность версии: перед ним маска становится альфой версии с растушёвкой 0 (`bakeMask`; картинка та же, поэтому шага отмены нет, а `MaskState` помнит растушёвку, и отмена прежних правок маски её возвращает), для правки сервер отдаёт альфу, браузер её не растушёвывает — иначе растушёвка вклейки (24 px) размывала бы любой край мазка, и мягкость 0 не давала бы чёткого. У такой версии «Расширить по правке» растушёвывает добавленное само, а «Ещё варианты» берут что видно больше чем наполовину и растушёвку вклейки по умолчанию. Поэтому после ответа сервера картинка не меняется, а синей заливки маски нет — только контур. Свои мазки маску из сервера не перезапрашивают; её перезапрашивают отмена и «Расширить по правке» (`maskChanged`) и ошибка мазка. Законченная правка держит превью, пока холст не догонит последний мазок. Сервер пересчитывает только участок около мазка (`applyShapesRegion`, `featherAlphaRegion` — побайтно как целиком, это проверяет тест).
- «Маска по объекту» («Маска ▾ → По объекту» в ленте версий и при правке маски; `objectMask` в `session.ts`, `src/core/object-mask.ts`): маску рисует сама модель генерации, выбранная в форме, — это генерация (в счётчике и журнале). Просьба — перекрасить ответ модели у версии на месте: объект белым, остальное чёрным (`objectMaskRequest`); на «нарисуй маску» ChatGPT рисовал новую картинку со своим масштабом и сдвигом. Модель получает кусок и он же с подсветкой того, что от версии видно, — по ней понимает, какой объект; объект словами не называется. Кусок не в пропорциях модели дополняется серыми полями. Сдвиг ответа на несколько пикселей исправляется (`alignMask`: край маски — на самые резкие перепады яркости рисунка); если половинам края нужны разные сдвиги (растянута больше чем на 3%) или сдвиг дальше 2% стороны — ошибка, а не кривая маска. Сравнения с холстом под версией и SAM здесь нет: от них по ChatGPT, который перерисовывает весь кусок, оставались кляксы на ступенях и камнях. Маска на 2 px шире с растушёвкой 2 px, как у слоя из выделения, сразу прозрачность (`bakeMask`); у текущей версии и область слоя становится объектом — его выделяет щелчок по слою и находит палочка. Шаг ⌘Z; генерация идёт десятки секунд мимо очереди правок, маску, поправленную за это время, не перебивает. У подставной модели маска — всё тёмное на куске (`mode: 'mask'` в `mock.ts`). Растянутой картинка считается, только если половинам края (лево-право, верх-низ) нужны разные сдвиги вдоль своей оси (по другой — общий) и свой сдвиг ложится на рисунок заметно лучше общего (`STRETCH_GAIN`): на рисунке тушью половина края, искавшая сдвиг в двух осях, находила штрихи рядом, и ровные маски ChatGPT отбрасывались как «растянутые» — так «Маска по объекту» молча не срабатывала. У исходника слоя-копии (⌘J, ⌘⇧J, объединённого) — так же, модель видит саму копию; у слоя из генерации исходник — то, что под ним, маски у него нет. Флажок «Маска по объекту» в форме (`objectMask` у задачи и в `RedoChange`, помнится между запусками) — то же сразу каждому варианту, легшему версией (`maskVariant`; у фона под слоем — нет): пока модель рисует маски, задача не закончена (`masking` у варианта, крутилка на плитке версии), «Отменить» их обрывает, «Остановить» шаги — нет (`masks`); маска, которая не вышла, — сообщением, версия остаётся с маской выделения. Вариант, легший не на холст, слой не растит: иначе он раздул бы область, уже ставшую объектом, обратно до выделения.
- «Скрыть от модели то, что под маской» (`hide`): модель получает один кусок, где область залита серым (`guide: 'blank'`), и рисует её заново, не держась за прежнее. Версия помнит это (и в .caaa), «Ещё варианты» идут так же.
- Генерация в слой: готовый вариант сразу ложится версией слоя задачи (`land`), «Принять» нет. Работают в слое (ниже; `object` у задачи) — его версия; иначе с первым готовым вариантом из выделения появляется новый слой с именем из задачи (`layerFromJob`, сверху всех). Первый готовый вариант сразу текущий, если пользователь, пока шли варианты, сам не выбрал версию (`picked`). Отдельной очереди в интерфейсе нет: ход генерации — в «Слоях» и в ленте версий (ниже); законченную задачу интерфейс сам убирает с сервера (`discard`), её варианты уже версии; задача с ошибкой остаётся, пока её не повторят или не уберут. Повтор с поправкой (`RedoChange`): «Поправить задачу» в ленте кладёт задачу версии в поле правки (ниже); новые варианты идут к прежним (`moreVariants`, `patchVariants`, у задачи с ошибкой — `retry`), промпт и картинки модели собираются заново (`retarget`), кусок и маска прежние; каждая версия помнит свою задачу и скрытие. После отправки правка очищается (задача, референсы, «С нуля»), модель, разрешение и число вариантов остаются.
- Раскладка окна (`App.tsx`, `styles.css`): холст в середине, под ним — лента версий (`VersionsBand`, тёмный «стол»: картинки — на столе, слова — на бумаге), справа — колонка: «Слои» во всю высоту и под ними правка (`compose`), прибитая к низу. Высота ленты и правки постоянная: выбор слоя, группы или генерации меняет только их содержимое, ничего не сдвигает. Синий — только то, что есть на холсте (выделение, «Видит модель», текущая версия, кольцо у миниатюры выбранной строки), кнопки — заливкой и чернилами (`--fill`, `--ink`).
- «Слои» (`LayersPanel`): дерево слоёв и групп сверху вниз (`layerTree` — то же, что на сервере). Строка слоя — миниатюра того, что от него видно (`/api/history/:id/thumb.png`, номер маски в адресе — кэш навсегда), рядом — миниатюра его маски, как в Photoshop (`mask-thumb.png`: прозрачность видимой версии на весь кусок; у исходника слоя из генерации маски нет): щелчок по ней — работа в слое и правка маски кистью (`maskLayer` — слой, а не версия: стала текущей другая версия — правится её маска), щелчок по строке слоя — снова его пиксели; синее кольцо — у того, что правят; имя, значки (идёт генерация, ошибка, под ним фон), «⋯» (видно под курсором: переименовать, дорисовать фон под ним, влить в фон, удалить; `MenuButton`) и глаз; строка группы — стрелка (свернуть, только в окне), папка, имя, «⋯» (переименовать, разгруппировать, удалить со слоями) и глаз (скрывает всё, что в ней; слои скрытой группы — тусклые, `visible` у слоя). В заголовке — «Группа» (⌘G) и «⋯» (объединить, свести все слои). Двойной щелчок — переименовать, и именно ту строку, по которой щёлкнули первый раз (`armRename`: второй щелчок в той же точке экрана; иначе второй щелчок по слою, в котором работают, вывел бы из него). Генерация нового слоя — строкой сверху, пока слой не появится; щелчок по ней (`activeJob`; новая генерация выбирается сама) — её ход или ошибка в ленте, а появился слой — работа сразу в нём. Строки слоёв и групп перетаскивают (`startDrag`, `dropAt`): у слоя верхняя половина строки — над ним, нижняя — под ним, у группы середина строки — в неё наверх; черта — с отступом того уровня, куда ляжет, в группу — рамка вокруг её строки; в саму себя и на своё место — нет; щелчок после перетаскивания ничего не выбирает; длинный список прокручивается, и у края при перетаскивании тоже. Последняя строка — «Фон» (к низу прилипает, только когда список длинный): щелчок по нему — работа вне слоёв и групп (`toBackground`: маски слоёв уходят из выделения, нарисованное остаётся); он выбран, когда работают не в слое, не в группе и не в генерации и слоёв в выделении нет. Заплатки фона — не строками, а в ленте своего слоя. На холсте — рамки только идущих генераций и генераций с ошибкой, с подписью слоя; число генераций с ошибкой — в верхней полосе, щелчок ведёт к первой (`showError`).
- Лента версий (`VersionsBand`; стрелка слева сворачивает её в строку, это помнится — `band-folded`): у слоя — «исх» и версии миниатюрами, идущие варианты — крутящимися плитками с «Остановить» (шаги) и «Отменить», ошибки — красными (щелчок — текст ошибки и «Повторить» в ленте, `errorJob`), «Ещё» — ещё варианты текущей. Щелчок по плитке — текущая версия; наведение — версия поверх холста, документ не меняется (`peek` → `setPeek` в `viewer.ts`: холст под слоем — `edit/below.jpg` видимой версии, сама версия — `cutout.png`, над ней — `edit/above.png`); двойной щелчок или F — холст по куску слоя (`toggleFocus`, ещё раз — вся картинка). В шапке — имя, «версия N из M · модель», «К куску», «Маска ▾» (по объекту, по правке; у исходника слоя-копии — только по объекту, у исходника слоя из генерации маски нет; править кистью — миниатюрой маски в «Слоях»), «Поправить задачу», удалить версию. Справа от плиток — колонка постоянной ширины: вкладки «Задача», «Директор», «Критик» (замечания критика хранятся у версии, `critique`, и в .caaa), предупреждение «почти ничего не изменила», ход и ошибка фона под слоем. У группы — её имя, «Разгруппировать» и «Удалить со слоями»; у нескольких слоёв (Shift-щелчок) — «Сгруппировать» и «Объединить»; у генерации нового слоя — её ход и «Остановить», «Отменить» или «Повторить»; у фона — недавние версии всех слоёв (щелчок открывает слой, наведение показывает версию).
- Правка (`compose` в `App.tsx`): поле задачи, в нём под текстом — референсы, набросок, «Стиль»; флажки «Директор», «Маска по объекту», «С нуля» (скрыть от модели, что под маской); модель и разрешение — сводкой (`ModelPicker`: окно со списком моделей, разрешением и подсказкой `SizeHint`; мало разрешения — сводка жёлтая); число вариантов или шагов; одна кнопка «Сгенерировать» с подписью — куда ляжет и сколько это генераций (варианты и маски по объекту) или почему нельзя (`blocked`: правка маски, слой или группа скрыты, нет выделения). Поправка задачи версии (`redoing`) — в том же поле: плашка «Поправка версии N» на месте вложений, свои «С нуля» и директор, модель — версии; черновик новой правки ждёт и возвращается (Esc или крестик). Esc в поле только уводит из него.
- Работа в слое (`active` в `App.tsx`): щелчок по слою в «Слоях», палочкой по нему на холсте (и ⌘J) — работа в нём: его маска ложится в выделение, палочка ищет в нём (`setLayer` в `viewer.ts`), холст не притушается — слой виден по выделению и строке в «Слоях»; на кнопке генерации — «в «…»», вне слоя — «новым слоем «…»» с именем из задачи. Выделение слой не меняет; Esc сначала снимает выделение, потом выходит из слоя; второй щелчок по слою в списке — тоже выход из него; ⌘ или Shift по слою в списке добавляет его маску к выделению и выходит из слоя: несколько слоёв правят новым слоем поверх них. Палочка ищет у хозяина точки (`pickObject`, `layerAt`, `Scope` в `segmentation.ts`): у каждой точки один хозяин — верхний видимый слой, чья маска её накрывает, или фон (всё, кроме видимых слоёв, `visibleLayers`, `clipOut`). Щелчок по другому слою — вход в него без модели (`enter`, выделен весь слой); по слою, где работают, — объект в его границах (уровни обрезаются, одинаковые сливаются); по фону — объект на фоне без кусков слоёв, работа вне слоя (`owner: null`). Добавить и вычесть (Shift, Alt, рамка) — только у того же хозяина, иначе `OUTSIDE_LAYER` сразу, до модели; интерфейс пишет «Вне слоя» или «Здесь слой». Подсветка под курсором так же: над другим слоем — весь слой. Прямоугольник, лассо и кисть — где угодно, выделение за краем слоя растит его маску (`land`). Правка части слоя (`base` и `part` у версии, `layerOver` в `edit-region.ts`): вариант ложится поверх версии слоя, которую модель видела (`visibleVersion`), поэтому остальной слой остаётся как был; «Ещё варианты» такой версии перерисовывают только `part` поверх `base` (`regionReplaced`). Весь слой в выделении (`whole` у задачи) — версия его заменяет: в ней только ответ модели, без `part`, прежняя версия в неё не копируется — иначе её край просвечивал бы сквозь растушёвку, и ни кисть, ни «Расширить по правке» его уже не убрали бы; маска такой задачи шире слоя на растушёвку (`ringed`) — по маске точно по слою весь его край выходил полупрозрачным, а тонкое (ствол) — насквозь; кольцо — не выделение: слой растёт только по выделенному (`claim`), «Ещё варианты» его не растят; `base` помнится, чтобы «Ещё варианты» видели то же, что модель в первый раз; их варианты тоже заменяют слой — и у версий из прежних, где правка накрыла слой целиком. В скрытый слой правка не идёт. Модель видит кусок в пунктирной рамке «Видит модель» (`setModelFrame`, `frame.inside` из `adviseSize`).
- «Ещё варианты» версии (`patchVariants`, `from`) — задача в очереди с той же задачей, маской версии, моделью, разрешением и референсами (версия их помнит, в .caaa тоже); модель видит холст без этой версии (`crop` в `prepareEdit`, `regionWithout`), сама версия — вариант №1, новые — новые версии того же слоя.
- Тайлы холста кэшируются браузером навсегда, а `rev` у каждого документа начинается с 1, поэтому в адресе тайла есть и id документа.
- Свой формат — проект `.caaa` (`project.ts`, версия 2): исходник, все слои с их группами (`groups` в описании, у слоя — `group`; прежние версии приложения группы пропускают) и все версии (и скрытые) с RGBA и маской до растушёвки (и версия, которую видела модель, `base`; у правки части слоя — и маска самой правки), текущая версия и видимость слоя, заплатки фона, стиль, dpi; после открытия холст побайтно тот же, история отмены пустая. Проект версии 1 (правки стопкой и объекты) при открытии переводится (`migrate`): каждая правка — слой с ней одной текущей версией, скрытая — скрытым слоем, фон отделённого объекта — заплатка, холст тот же. PNG исходника кэшируется по буферу `doc.base`, поэтому повторное сохранение быстрое. В Finder `.caaa` открывается двойным щелчком (`fileAssociations` в package.json, `open-file` в `main.ts`).
- Сохранение: проект `.caaa` «Сохранить» пишет без вопросов. Картинка со слоями сначала спрашивает «Сохранить слои?»: в .caaa или слить в картинку; после записи картинкой (`flattened`) больше не спрашивает до открытия другого документа. «Экспортировать картинку…» пишет копию, не меняя файл документа. Картинку «Сохранить» перезаписывает (так решил пользователь), но только если это без потерь — `inspectImage` запрещает перезапись при прозрачности, >8 бит, не-sRGB профиле, CMYK, TIFF, нескольких кадрах; тогда — «Сохранить как». Запись через временный файл и rename. Окна выбора файла и вопросы «Сохранить изменения?» даёт `Host` (`session.ts`), его реализует Electron; у сервера для разработки окон нет — там «Сохранить как» скачивает PNG. Недавние файлы сервера для разработки — отдельный список (`<папка данных>/dev`). «Не сохранено» считается по содержимому: `contentKey` документа (включённые правки по порядку) сравнивается с сохранённым, поэтому отмена до сохранённого состояния снимает метку; у проекта .caaa ещё и стиль. Закрытие окна и выход (⌘Q) с несохранённым спрашивают «Сохранить изменения?» — это проверяет `--smoke`.
- `src/server/` — `session.ts` (документ и очередь задач: не больше 2 одновременно), `app.ts` (HTTP на 127.0.0.1: проверка Host и заголовок `x-canvaaaas` у изменяющих запросов), `main.ts` (сервер без Electron).
- `src/shared/api.ts` — типы API, общие для сервера и интерфейса, и команды меню (`AppCommand`). `src/renderer/` — интерфейс: `viewer.ts` (OpenSeadragon + оверлей выделения и наброска, он рисуется один раз за проход OpenSeadragon — `drawPass`: `animation` и `update-viewport` приходят в одном кадре; прокрутка двумя пальцами и колесо двигают картинку, щипок и ⌘ + колесо масштабируют; клавиатура OpenSeadragon выключена — её R, S, W, A, D, F спорят с клавишами инструментов), `App.tsx`. Иконки — только Tabler (`@tabler/icons-preact`), своих SVG не рисуем.
- Стиль документа — кнопка «Стиль» в поле правки (подсвечена, когда стиль задан; он же во всплывающей подсказке) и окно `StyleDialog` (⌘↵ — сохранить, Esc — передумать); поля на панели нет.
- Язык (`src/shared/i18n.ts`): каждый текст интерфейса, меню, окон, ошибок сервера и CLI — парой `L('по-русски', 'in English')`, по-английски в кавычках «…» становятся “…”, апостроф — ’. Склонения — `plural(n, [1, 2–4, 5], [one, other])`, дробные числа — `decimal`, даты — `locale()`. `L()` читает язык в момент вызова: на уровне модуля — только в `App.tsx` и том, что он импортирует (`main.tsx` грузит его динамически после `/api/lang`); в сервере, ядре, `shared/api.ts` и `electron/main.ts` — только в функциях (`fillTask`, `canvasPresets`, `projectFilter`). Язык выбирает `Session`: `systemLang` (Electron — первый из `app.getPreferredSystemLanguages()`, сервер для разработки и CLI — `system-lang.ts`: на macOS `AppleLanguages`; `CANVAAAAS_LANG=en|ru` главнее) и выбор в настройках (`lang` в prefs: `system`, `en`, `ru`; `/api/lang`, «Язык» в окне настроек). Смена — меню пересобирается (`lang()` в его ключе), окно перезагружается. Поток SAM получает язык в `workerData`. Идентификаторы не переводятся: «разрешение» ChatGPT `CHATGPT_SIZE` = '1,6 Мп' хранится в проектах — переводится только подпись; `OUTSIDE_LAYER` интерфейс узнаёт по тексту. Тесты идут по-русски (`test/setup.ts`); `test/i18n.test.ts` — язык.
- Тексты в интерфейсе — короткие подписи без объяснений. Пояснение, если без него никак, — за значком «?» рядом (`Help` в `App.tsx`: окно по щелчку, в `document.body`). Снять выделение — ⌘D (меню «Правка»), Esc или кнопка справа на панели над холстом; ⌘Z в форме убирает последнюю фигуру или штрих наброска.
- Мягкая кисть (`softness` у мазка, 0..1) — только при правке маски слоя или задачи, выделение всегда жёсткое. Сервер растеризует её в `mask-shapes.ts` размытием по Гауссу (линия уже на половину зоны затухания, σ = зона/5), превью в `viewer.ts` повторяет то же через `ctx.filter`. `src/electron/main.ts` — окно и меню: пункты меню шлют `AppCommand` в окно событием `canvaaaas-command`, их сочетания клавиш не регистрируются (`registerAccelerator: false`) и обрабатываются интерфейсом — кроме «Отменить»/«Повторить», без которых на macOS не работает отмена в полях ввода. Настройки — только из меню (⌘,), не кнопкой в интерфейсе. «Открыть…» — тоже только из меню (⌘O) и со стартового экрана, в верхней полосе его нет.
- Промпт для модели собирает `buildPrompt` (`edit-region.ts`): задача первой и как обязательная — осторожная формулировка («верни картинку, всё сохрани») давала ответы почти без изменений. В статистике варианта есть `insideChangedPct`; ниже 2% интерфейс предупреждает, что правка не случилась.
- Слой из выделения (⌘J, `saveObject`): копия того, что сейчас видно в выделении (`lift`, маска на 2 px шире — с контуром), новым слоем сверху всех; другие слои не трогаются, правки под ним его больше не меняют. «Вырезать в слой» (⌘⇧J, `cutObject`) — то же, но на старом месте дыра у того, чьи пиксели там видны (верхняя версия с альфой): в слое — маска его видимой версии теряет этот кусок, а область слоя (маска `DocObject`) прежняя, поэтому дыра — его; в фоне — белое место (`setBase`). Дыра — по выделению, копия — на 2 px шире, поэтому, пока слой на месте, картинка побайтно та же. Генерации нет. Слой помнит, откуда его вырезали (`hole`, со сдвигом не едет, в .caaa тоже) и что под ним его больше нет (`freed`). Новый слой из генерации тоже ложится сверху. Записи слоёв не меняются на месте, любое изменение — шаг ⌘Z (`setObjects`, пересобирает участки, где видимые версии поменялись); в .caaa маски — PNG. Слой в выделении — фигура `kind: 'mask'` (`obj:id` или id маски под щелчком), задача берёт маски сразу (`resolveShapes`). Слои входят в «не сохранено»; картинкой их не сохранить — «Сохранить» спрашивает «Сохранить слои?».
- Выделение объектов (`segment.ts`, `segment-model.ts`, `server/segmentation.ts`): SAM 2.1 base+ (Meta, Apache 2.0), ONNX-сборка AnyLabeling. Веса ~290 МБ не в сборке: скачиваются по кнопке в папку данных приложения (`models/`), не в Dropbox, архив сверяется по SHA-256 и распаковывается своим разбором zip; `CANVAAAAS_SAM_DIR` — другая папка. Признаки считаются по видимой части холста (по всей картинке края объектов — каша), заранее, когда вид остановился (`/api/segment/view`, устаревший вид не считается); подсветка под курсором — `hover.png`, щелчок даёт до 3 уровней «деталь / часть / целое» (`levels`), мелкий для вида объект уточняется вторым проходом (`refine`). Маски декодера чистятся на сетке (`cleanLogits`): мелкие дыры внутри (на штриховке — «шахматкой») заделываются, крошки вокруг убираются, крупный проём остаётся. Инструмент «Палочка» (W, в коде `object`; палочки по яркости нет — выделяет только объекты): щелчок — по режиму выделения (ниже), туда же или [ ] — уровень мельче или крупнее (и переключатель «Деталь / Часть / Целое» на панели), рамка — объект внутри неё. «По линиям» (`snap` у `PickRequest` и уточнения) привязывает маски уровней к линиям рисунка. При «Добавить» и «Вычесть» щелчок несёт выделение (`op`, `selection`): если уровень модели его не меняет (весь уже выделен), первым идёт ближайший мельче, который меняет, — крупнее нельзя, иначе щелчок внутри выделенного добавлял бы фон; не меняет никакой — `unchanged`, интерфейс так и говорит. Модель считает в своём потоке (`segment-worker.ts`, worker_threads): onnxruntime-node держит поток, пока считает (кодировщик — секунды), а сервер приложения живёт в главном процессе Electron — без отдельного потока замирали тайлы и всё окно. Признаки участков лежат в потоке (`Embedding` — только id; поток помнит 8, сервер 4, попадание в кэш сервера освежает их и там — `touch`). `/api/segment/view` отвечает сразу, не дожидаясь признаков: иначе запрос держал бы одно из шести соединений браузера и тайлы ждали бы. Итоги разведки — `docs/recon-objects.md`.
- Панель настроек инструмента — строка над холстом (`optbar` в `App.tsx`): у инструментов выделения режим «Новое / Добавить / Вычесть» (`SelectOp`; Shift и ⌘ — добавить, Alt — вычесть на время щелчка, у всех инструментов как в Photoshop; кисть не заменяет; ластика нет — это кисть с «Вычесть», у неё тогда белое кольцо) и «Край» — ползунок ±50 px, как «Размер» и «Мягкость» (`/api/selection/edge`: всё выделение одной маской шире или уже, считается от выделения до первого сдвига края); пока есть выделение, при любом инструменте справа — «Слой из выделения» (⌘J) и «Снять выделение» (⌘D); у правки маски слоя — «Вернуть / Скрыть» (`maskOp`, `setMaskErase` в `viewer.ts`: кисть и фигуры; Alt — наоборот, X — сменить; правка начинается со «Скрыть»), размер, мягкость, «По объекту» и «Готово». Слева — только инструменты. Настройки инструментов и формы (модель, разрешение, число вариантов и шагов, директор) помнятся между запусками (`usePref`): их хранит сервер в `prefs.json` в папке данных приложения (`prefs.ts`, `/api/prefs`; у сервера для разработки — в `dev/`), окно читает их раз до первой отрисовки (`loadPrefs` в `main.tsx`). Не localStorage: сервер приложения каждый запуск на новом порту, у окна другой адрес, и память браузера пустая.
- Линии рисунка (`src/core/lines.ts`): светлые области между тёмными линиями, щели до 2·gap px закрыты (`lineMap`). `snapToLines` — область, которую маска покрывает почти целиком, берётся вся, едва задетая выбрасывается, протёкшая через щель остаётся как в маске, тёмное под маской, которое без разрыва примыкает к взятому, тоже берётся (сплошь тёмное — кудри, чёрная одежда — не линия, светлых областей в нём нет, и без этого палочка «По линиям» теряла волосы), линии рядом со взятым — контур; у мазка кисти (`reach`, «По линиям» у кисти, `/api/selection/snap`) нарисованное остаётся, клетки, которые он почти накрыл, добавляются. Маски края и мазков хранятся там же, где маски объектов под щелчком (`Segmentation.keep`).
- Меню «Слой» (только меню и клавиши, кнопок нет, кроме полосы при нескольких слоях в выделении): «Сгруппировать слои» (⌘G), «Разгруппировать» (⇧⌘G) — выше, у групп. «Объединить слои» (⌘E, `mergeLayers`) — слои в выделении (Shift-щелчком в списке) и тот, в котором работают, одной картинкой того, что сейчас видно (`layerOver` по порядку), версии уходят; новый слой встаёт на место верхнего с его именем, заплатки фона переходят под него. «Влить в фон» (`mergeIntoBase`, и в меню «⋯» слоя) — видимое от слоя (с частями и заплаткой фона) вписывается в исходник (`setBase`), слой с версиями уходит; нельзя, если под ним видны другие слои (`layersOverlap`) — в исходнике он оказался бы под ними. «Свести все слои» (`flattenLayers`) — видимое становится исходником, все слои (и скрытые) уходят. Всё — одним шагом ⌘Z. Исходник с тех пор меняется: `baseState` (номер его состояния, отмена возвращает прежний) входит в `contentKey`, в адрес тайлов «\» и в кэш PNG исходника проекта; «\» показывает исходник с влитым.
- Фон под слоем (`fillUnder` в `session.ts`): «Дорисовать фон под слоем» («⋯» у слоя или глаз у слоя-копии, под которым он сам) — там, где дыра: у вырезанного — откуда вырезали (`hole`), у остальных — под ним сейчас. Область шире на растушёвку вклейки и ещё 2% (`fillGrow`: иначе дорисованное лежит на контуре не целиком и старый контур просвечивает). Каждая её точка — у верхнего слоя под ним, чья маска её накрывает (`layersBelow`), или у фона; дорисовывают только те, у кого есть часть самой дыры, запас вокруг у остальных достаётся главному из них. По задаче на слой (`fillFor`, скрытие, `FILL_TASK`): вариант — версия этого слоя поверх его видимой (как правка части слоя, слой подрастает); у фона — новый слой в самом низу «Фон под «…»» (`bottom`), его потом можно влить в фон. Заплатки `kind: 'fill'` прямо под слоем бывают только в старых проектах (их варианты — в ленте своего слоя). Дальше без генераций: «Сдвинуть» (V) тянет слой (`moveObject`: все его версии, исходник, части и их версии, всё остаётся на холсте; превью в браузере — `below` и `cutout.png` версии на холсте), глаз скрывает, кисть «Скрыть» по маске исходника стирает часть (и из маски слоя), «Убрать с холста» удаляет слой с частями, заплатка остаётся. Сдвинуть можно и слой без фона, если у него свои пиксели (копия или версия): на старом месте — то, что под ним, как в Photoshop (`freed` — под слоем его самого больше нет). Маски слоёв сами не пересчитываются: у слоя свои пиксели, и его маску меняют только его генерации, кисть выделения и правка маски его видимой версии — кисть маски, «Расширить по правке», «Маска по объекту» (`followMask`: область слоя — маска этой версии, тем же шагом ⌘Z; иначе выделение слоя и поиск палочкой в нём резали бы то, что от него видно) (`lost` — только у слоёв из старых проектов).
